Use this to cover quality attributes, risks and key decisions.

- For each non-functional requirement, explain how the design meets it
  (caching, pagination, indexes, retries, timeouts, rate limits, validation,
  encryption, monitoring).
- Observability: what to log, which metrics and alerts matter.
- Failure handling: what happens when a dependency is slow or down.
- Key decisions: for each important choice write the decision, the
  alternatives considered and why this one was chosen (a short ADR).
- Risks and open questions: anything uncertain, with its impact and how to
  reduce it. Include assumptions the user has not confirmed.
