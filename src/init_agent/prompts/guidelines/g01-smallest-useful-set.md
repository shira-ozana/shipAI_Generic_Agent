Start with `AGENTS.md`, `ARCHITECTURE.md`, `RULES.md`, and the skills the evidence
supports. Add `DEVELOPMENT.md` or `TESTING.md` only when the commands do not fit in
a short section of `AGENTS.md`. Add `DOMAIN.md` and `CONTRACTS.md` when the
repository has a clear business vocabulary or API contracts that Requirements and
Architect need.
